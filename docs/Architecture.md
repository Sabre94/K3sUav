## 核心组件详解

### 1. **UAV Agent (数据收集层)**
- **部署方式**: DaemonSet（每个节点一个）
- **主要功能**:
  - 收集节点指标（GPS、电量、网络等）
  - 支持模拟模式（从 JSON 文件读取）
  - 智能推送：基于变化阈值，减少 API 调用 62.5%
  - 位置变化 > 5m 或电量变化 > 1% 才推送
- **代码位置**: `cmd/agent/main.go`
- **镜像**: `x1224403599/uav-agent:v0.3.0`

### 2. **UAVMetrics CRD (数据存储层)**
- **类型**: Kubernetes 自定义资源
- **存储内容**:
  ```yaml
  spec:
    nodeName: drone-workers-0
    gpsLatitude: 34.0522
    gpsLongitude: -118.2437
    position:
      x: 8856.83
      y: 0
      z: 10
    velocity:
      vx: 0.5
      vy: 0.3
      vz: 0
    batteryLevel: 85.5
    networkLatency: 45.2
    simulation:
      vmId: "vm-001"
      simulationId: "sim-123"
  ```
- **代码位置**: `api/crd/uav-metrics-crd.yaml`

### 3. **UAV Scheduler (单 Pod 调度层，可选)**
- **部署方式**: Deployment (1 副本)
- **职责**: 为单个 Pod 选择最优节点
- **算法**:
  - `distance-based`: 基于距离
  - `battery-aware`: 基于电量
  - `composite`: 组合算法
  - `greed-nsgaii`: 贪心 + NSGA-II
- **问题**: 逐个调度 Pod，无法全局优化
- **代码位置**: `cmd/scheduler/main.go`
- **镜像**: `x1224403599/uav-scheduler:v0.3.1`

### 4. **Task Controller (任务自动化层，新增核心)**
- **部署方式**: Deployment (1 副本)
- **职责**: 全局优化，自动化任务部署
- **工作流程**:
  ```
  监听 UAVTask 创建
    ↓
  读取所有 UAVMetrics (12个节点)
    ↓
  运行 NSGA-II 算法
    ↓
  计算结果: 需要 8 个节点
    ↓
  自动创建 8 个 Pod 并绑定到节点
    ↓
  更新 UAVTask 状态
  ```
- **优势**:
  - ✅ 用户无需指定副本数
  - ✅ 全局优化，不是逐个调度
  - ✅ 保证覆盖率目标
  - ✅ 多目标优化（覆盖+电量+延迟）
- **代码位置**: `cmd/task-controller/main.go`
- **镜像**: `x1224403599/uav-task-controller:v0.1.0`

### 5. **UAVTask CRD (任务定义层)**
- **类型**: Kubernetes 自定义资源
- **用户体验**:
  ```yaml
  # 用户只需写这个
  apiVersion: uav.k3s.io/v1
  kind: UAVTask
  metadata:
    name: my-task
  spec:
    targetCoverage: 0.9    # 90%覆盖率
    coverageRadius: 500    # 500米半径
    template:              # Pod 模板
      spec:
        containers:
        - name: app
          image: nginx:alpine

  # ❌ 不需要写 replicas: 10
  # ✅ 系统自动计算需要 8 个节点
  ```
- **代码位置**: `api/crd/uav-task-crd.yaml`

## 数据流向

```
用户创建 UAVTask
  ↓
Task Controller 检测到
  ↓
读取 12 个节点的 UAVMetrics
  ↓
NSGA-II 算法计算
  ├─ 目标1: 覆盖率 ≥ 90%
  ├─ 目标2: 总电量最高
  ├─ 目标3: 平均延迟最低
  └─ 目标4: 节点数最少
  ↓
Pareto 最优解: 选择 8 个节点
  [drone-masters-0, drone-masters-1,
   drone-workers-0...drone-workers-5]
  ↓
创建 8 个 Pod
  Pod-0 → nodeName: drone-masters-0
  Pod-1 → nodeName: drone-masters-1
  ...
  Pod-7 → nodeName: drone-workers-5
  ↓
更新 UAVTask 状态
  status:
    phase: Running
    nodeCount: 8
    podCount: 8
    coverageRatio: 0.92
    selectedNodes: [...]
```

## 算法架构

### NSGA-II 多目标优化算法

```
┌───────────────────────────────────────┐
│  输入: UAVMetrics (12个节点)          │
│  - GPS 坐标                            │
│  - 位置坐标 (x,y,z)                   │
│  - 电量                                │
│  - 网络延迟                            │
└────────────┬──────────────────────────┘
             ▼
┌───────────────────────────────────────┐
│  Step 1: 初始化种群                    │
│  - 随机生成 50 个节点组合               │
│  - 每个组合包含不同数量的节点            │
└────────────┬──────────────────────────┘
             ▼
┌───────────────────────────────────────┐
│  Step 2: 计算覆盖率                    │
│  - 将区域划分为网格 (50x50)            │
│  - 计算每个节点的覆盖圆                 │
│  - 统计被覆盖的网格数                   │
│  - 覆盖率 = 覆盖网格数 / 总网格数       │
└────────────┬──────────────────────────┘
             ▼
┌───────────────────────────────────────┐
│  Step 3: 评估适应度 (4个目标)          │
│  - f1: 最大化覆盖率                    │
│  - f2: 最大化平均电量                   │
│  - f3: 最小化平均延迟                   │
│  - f4: 最小化节点数                     │
└────────────┬──────────────────────────┘
             ▼
┌───────────────────────────────────────┐
│  Step 4: 非支配排序                    │
│  - 找出 Pareto 最优解                  │
│  - 解A 支配 解B: A 在所有目标都不差于B │
│  - 且至少一个目标优于B                  │
└────────────┬──────────────────────────┘
             ▼
┌───────────────────────────────────────┐
│  Step 5: 选择、交叉、变异 (30代)       │
│  - 选择: 锦标赛选择                     │
│  - 交叉: 节点集合交叉                   │
│  - 变异: 添加/删除节点                  │
└────────────┬──────────────────────────┘
             ▼
┌───────────────────────────────────────┐
│  输出: Pareto 前沿                     │
│  选择第一个解（平衡所有目标）            │
│  - 节点数: 8                           │
│  - 覆盖率: 92%                         │
│  - 平均电量: 85%                        │
│  - 平均延迟: 45ms                       │
└───────────────────────────────────────┘
```

## 对比：传统方式 vs 新架构

### 传统 Deployment 方式

```yaml
# 用户需要：
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 10  # ❌ 手动猜测需要多少个
  template:
    spec:
      schedulerName: uav-scheduler
      containers:
      - name: app
        image: nginx:alpine

# 结果：
# - 10 个 Pod 逐个调度
# - 可能都调度到 1 个节点（贪心局部最优）
# - 覆盖率无法保证
# - 需要重规划机制补救
```

### 新 UAVTask 方式

```yaml
# 用户只需：
apiVersion: uav.k3s.io/v1
kind: UAVTask
metadata:
  name: my-task
spec:
  targetCoverage: 0.9  # ✅ 指定目标覆盖率
  template:
    spec:
      containers:
      - name: app
        image: nginx:alpine

# 结果：
# - 系统自动计算需要 8 个节点
# - 全局优化，保证 90% 覆盖率
# - 直接绑定到最优节点
# - 一次到位，无需补救
```

## 关键技术点

### 1. **智能推送机制** (Agent)
```go
// 只在显著变化时推送
if positionChange > 5.0 meters || batteryChange > 1.0% {
    updateMetrics()
}
// 减少 API 调用 62.5%
```

### 2. **多目标优化** (NSGA-II)
```go
objectives := []float64{
    -coverage,         // 最大化覆盖率
    -avgBattery,       // 最大化电量
    avgLatency,        // 最小化延迟
    float64(nodeCount) // 最小化节点数
}
```

### 3. **直接节点绑定** (Task Controller)
```go
pod.Spec.NodeName = selectedNode  // 跳过调度器，直接绑定
k8sClient.Create(ctx, pod)
```

### 4. **状态追踪** (UAVTask Status)
```yaml
status:
  phase: Running
  nodeCount: 8
  podCount: 8
  coverageRatio: 0.92
  selectedNodes: [...]
  lastUpdateTime: 2026-01-11T10:00:00Z
```

## 总结

这是一个**三层架构**：

1. **数据层**: UAV Agent → UAVMetrics CRD
2. **计算层**: Task Controller + NSGA-II 算法
3. **执行层**: 自动创建 Pod 并绑定节点

**核心创新**：用户无需指定副本数，系统自动计算最优部署方案。
